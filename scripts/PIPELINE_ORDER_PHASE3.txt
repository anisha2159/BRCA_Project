================================================================================
BRCA PROJECT - R PIPELINE
What each script does, in the order they must be executed
================================================================================

How to run everything
---------------------
    cd ~/Desktop/BRCA_Project
    Rscript scripts/run_all.R

run_all.R sets the working directory to the project root, runs the 18 scripts
below in this exact order, and appends the console output (stdout + stderr) of
every script into ONE combined file:

    results/run_all_output.txt

Requirements
------------
    R 4.x
    packages: data.table, DESeq2, ggplot2, pheatmap

    pheatmap is only needed by script 15. It is NOT installed in this R library
    right now, so 15 fails until you run:  install.packages("pheatmap")
    run_all.R records that failure and keeps going.

    Every script resolves inputs relative to the project root (for example
    "data/processed/..."), which is why they must be run from that directory.
    Scripts 1, 2 and 10 write nothing at all - their value is printed to the
    terminal, which run_all.R captures into the combined log.

Raw inputs the pipeline expects on disk
---------------------------------------
    data/raw/gdc_sample_sheet.2026-11-04.tsv        tumour sample sheet (GDC)
    data/raw/gdc_manifest.txt                        file IDs of downloaded files
    data/raw/normal_metadata/normal_sample_metadata.tsv
    data/raw/expression/<file_id>/<file_name>        109 tumour STAR count files
    data/raw/expression_normal/<file_id>/<file_name> 109 normal STAR count files

================================================================================
PHASE 0 - LOOK AT THE RAW DATA (read-only, no dependencies)
================================================================================

1) inspect_data.R
   Purpose : Understand the shape of one STAR counts file.
   Reads   : the first .tsv found under data/raw/expression (recursive).
   Writes  : nothing.
   Does    : lists all expression files and counts them; reads the first one
             skipping its 1-line header comment; prints rows, columns, column
             names and the first 6 rows; counts the STAR alignment-summary
             rows (gene IDs starting with "N_") that must be discarded;
             reports unique and duplicated gene IDs.
   Why it matters: tells you the real column layout ("unstranded" holds the
             counts) and that each file is 60664 data rows under its header
             line, of which 4 are STAR "N_" summary rows, leaving 60660 genes.

2) inspect_metadata.R
   Purpose : Understand the GDC sample sheet and confirm the download matches.
   Reads   : data/raw/gdc_sample_sheet.2026-11-04.tsv, data/raw/gdc_manifest.txt,
             directory listing of data/raw/expression.
   Writes  : nothing.
   Does    : prints sample-sheet size and column names; tissue-type and
             tumour-descriptor frequency tables; unique Case IDs and Sample
             IDs plus duplicated-sample count; cross-checks sheet File IDs
             against the manifest IDs in both directions; counts expression
             TSVs on disk and how many filenames appear in the sheet; shows
             the first 10 specimen rows.
   Why it matters: proves the downloaded files and the metadata agree before
             any sample is trusted.

3) inspect_batch_metadata.R
   Purpose : Inventory the metadata columns to see whether a batch variable
             even exists (input for the batch-effect decision in phase 6).
   Reads   : tumour sample sheet + normal metadata.
   Writes  : results/phase3_qc/tables/batch_metadata_inventory.tsv
   Does    : for each column of each table records missing values and number
             of unique values, stacked into one inventory with a dataset tag.

================================================================================
PHASE 1 - DEFINE THE ANALYSIS COHORT
================================================================================

4) build_sample_manifest.R
   Purpose : Build the paired tumour/normal sample list. THE GATEKEEPER - every
             script after this one reads its output.
   Reads   : tumour sample sheet + normal metadata.
   Writes  : data/processed/final_sample_manifest.tsv
   Does    : intersects tumour Case IDs with the normal patient column, then
             removes 4 patients that carry more than one tumour SAMPLE ID
             (TCGA-A7-A0DB, TCGA-A7-A0DC, TCGA-A7-A13E, TCGA-A7-A13G);
             selects exactly one tumour file and its matching normal file per
             patient; builds file_path for each condition; hard-stops unless
             the result is exactly 109 tumour + 109 normal = 218 samples over
             109 patients with 1:1 pairing, no duplicate File IDs, and every
             expression file present on disk.
   Output columns: patient_id, sample_id, file_id, file_name, condition, file_path

================================================================================
PHASE 2 - BUILD AND PROVE THE COUNT MATRIX
================================================================================

5) build_count_matrix.R
   Purpose : Assemble the raw gene-by-sample count matrix. Slowest script
             (parses all 218 expression files).
   Reads   : data/processed/final_sample_manifest.tsv (from script 4),
             all 218 expression files.
   Writes  : data/processed/gene_counts_matrix.rds
             data/processed/gene_annotation.tsv
   Does    : reads the first listed file as the gene reference and drops its
             "N_" summary rows; allocates an integer matrix of 60660 reference
             genes x 218 samples; for each file re-checks that gene IDs are
             unique and set-equal to the reference, row-matches them into
             reference order, and validates the counts are non-NA, >= 0,
             whole numbers, below .Machine$integer.max; also verifies the
             gene_name / gene_type annotations are identical across files.
             Sample columns are named <patient_id>__<condition> so tumour and
             normal of the same patient never collide.
   Why it matters: this is the only authoritative raw-count object; everything
             downstream is derived from it.

6) validate_count_matrix.R
   Purpose : Independently re-validate what script 5 persisted.
   Reads   : gene_counts_matrix.rds, gene_annotation.tsv, final_sample_manifest.tsv
   Writes  : nothing (stopifnot gate).
   Does    : asserts 60660 x 218 dimensions and integer storage mode, unique
             non-NA gene IDs and column IDs, matrix columns set-equal to the
             manifest's patient__condition keys, annotation rows identical to
             matrix rows, no NA and no negative counts, exactly one sample per
             patient/condition (218 groups), and prints condition totals,
             all-zero genes, and min/max counts.
   Note    : 60660 is not arbitrary - it is exactly the gene count that
             survives in every file once the header line and the 4 "N_"
             STAR summary rows are removed from the 60664 data rows.

================================================================================
PHASE 3 - QUALITY CONTROL ON RAW COUNTS
================================================================================

7) inspect_expression_distributions.R
   Purpose : Per-sample expression shape - library size, genes detected,
             extreme values.
   Reads   : data/processed/gene_counts_matrix.rds
   Writes  : results/phase3_qc/sample_expression_summary.tsv
             results/phase3_qc/plots/library_size_distribution.png
             results/phase3_qc/plots/detected_genes_distribution.png
   Does    : computes total counts, genes with count > 0, median/mean/P99/max
             per sample, tags each sample Tumor or Normal from its column name,
             lists the 10 samples with the largest single-gene count and the
             10 genes with the largest count anywhere, and draws two boxplots
             (log10 library size, detected genes).
   Why it matters: this is the summary table quoted in the final report.

8) inspect_sample_outliers.R
   Purpose : Decide which samples look technically abnormal, statistically.
   Reads   : gene_counts_matrix.rds, final_sample_manifest.tsv
   Writes  : results/phase3_qc/sample_outlier_summary.tsv
   Does    : rebuilds the same QC metrics, joins them to the manifest in matrix
             column order, then applies a MAD-based robust outlier test
             (|x - median| / MAD > 3.5, MAD rescaled by 1.4826) separately
             WITHIN tumours and WITHIN normals to log10 library size and to
             detected-gene count; a sample is flagged if either metric is
             extreme. Prints the flagged rows.
   Why it matters: this is the test that surfaced TCGA-BH-A0DZ__Tumor.

9) inspect_gene_variance.R
   Purpose : Gene-level filter survey (exploratory, NOT applied).
   Reads   : data/processed/gene_counts_matrix.rds
   Writes  : results/phase3_qc/gene_variance_summary.tsv
   Does    : per-gene variance, count of zero-variance genes, number of samples
             with >= 10 counts per gene, and a pass flag requiring at least
             ceiling(10% x 218) = 22 such samples.
   Important: it only records which genes WOULD pass. The matrix that scripts
             11-16 use is still the full unfiltered matrix.

10) inspect_flagged_pair.R
    Purpose : Forensics on the one flagged patient before any exclusion call.
    Reads   : gene_counts_matrix.rds, final_sample_manifest.tsv
    Writes  : nothing.
    Does    : takes TCGA-BH-A0DZ, checks it really has one tumour and one
              normal, prints both QC rows, and reports the percentile of each
              sample's detected-gene count and library size against all other
              samples of the SAME condition.

================================================================================
PHASE 4 - NORMALIZATION AND TRANSFORMATION (needs DESeq2)
================================================================================

11) normalize_counts_deseq2.R
    Purpose : Library-size normalization that respects the paired design.
    Reads   : gene_counts_matrix.rds, final_sample_manifest.tsv
    Writes  : data/processed/normalized_counts.rds
              results/phase3_qc/size_factors.tsv
    Does    : builds colData aligned to matrix columns, sets condition factor
              levels (Normal reference, then Tumor), makes a DESeqDataSet with
              design = ~ patient_id + condition, runs estimateSizeFactors only
              (median-of-ratios), extracts normalized counts and the per-sample
              size factors; verifies every size factor is finite and positive.
              No differential-expression test is run in this phase.
    Note    : ~ patient_id + condition means each tumour is compared against
              its own normal; patient absorbs the between-patient variation.

12) apply_vst.R
    Purpose : Variance-stabilized values for plotting and clustering.
    Reads   : gene_counts_matrix.rds, final_sample_manifest.tsv
              (rebuilds the same DESeqDataSet as script 11)
    Writes  : data/processed/vst_counts.rds
              data/processed/vst_object.rds
    Does    : estimates size factors again, applies vst(blind = FALSE) so the
              shrinkage uses the paired design, saves the transformed matrix
              and the full DESeqTransform object; reports dimensions, NA,
              infinite values and the value summary.
    Why it matters: vst_object.rds is what the PCA needs; vst_counts.rds is
              what the distribution plot and correlation heatmap need.

================================================================================
PHASE 5 - PLOTS FROM TRANSFORMED DATA (needs scripts 11-12)
================================================================================

13) plot_expression_distribution.R
    Purpose : Visual sanity check after transformation.
    Reads   : data/processed/vst_counts.rds
    Writes  : results/phase3_qc/plots/vst_expression_distribution.png
    Does    : melts the matrix to long format and draws one boxplot per sample
              with outliers hidden, 14 x 7 in at 300 dpi.

14) plot_pca.R
    Purpose : Global structure - do tumour and normal separate?
    Reads   : data/processed/vst_object.rds, final_sample_manifest.tsv
    Writes  : results/phase3_qc/plots/pca_condition.png
    Does    : runs plotPCA(intgroup = "condition"), attaches patient IDs, saves
              PC1/PC2 percentage variance in the axis labels, prints them.
    Note    : each patient contributes one tumour and one normal, so look for
              whether the two conditions separate along PC1/PC2 or whether the
              variance is instead dominated by patient structure. This plot is
              a QC view, not the tumour-vs-normal test - that comes later.

15) plot_sample_correlation.R
    Purpose : Sample-to-sample similarity and pairing check.
    Reads   : data/processed/vst_counts.rds, final_sample_manifest.tsv
    Writes  : data/processed/sample_correlation_matrix.rds
              results/phase3_qc/plots/sample_correlation_heatmap.png
    Does    : pairwise-complete Pearson correlation across the 218 VST columns,
              clusters with complete linkage, annotates rows and columns by
              condition and patient, prints the correlation range.
    Requires: pheatmap - the only script that fails without it.

================================================================================
PHASE 6 - FINALIZE THE PROCESSED DATASET AND WRITE THE REPORTS
================================================================================

16) finalize_phase3_data.R
    Purpose : Lock in one clean metadata object for phase 4 onward.
    Reads   : gene_counts_matrix.rds, normalized_counts.rds, vst_counts.rds,
              final_sample_manifest.tsv
    Writes  : data/processed/clean_sample_metadata.rds
              data/processed/clean_sample_metadata.tsv
    Does    : stopifnot-checks that all three matrices share identical column
              AND row names, that there are 218 rows over 109 patients with
              109 tumour and 109 normal, that normalized and VST values are
              finite and normalized counts are non-negative; then stores
              condition as a Normal-before-Tumor factor and patient_id as a
              factor, in matrix column order.

17) generate_normalization_report.R
    Purpose : One small numeric summary of the normalization step.
    Reads   : results/phase3_qc/size_factors.tsv (from script 11)
    Writes  : results/phase3_qc/reports/normalization_summary.tsv
    Does    : metric/value table of sample count, min, Q1, median, mean, Q3,
              max and the number of size factors that are not finite or <= 0.
    Note    : it does not create reports/ itself; run_all.R creates all output
              directories before the first script starts.

18) generate_phase3_report.R
    Purpose : The written record of phase 3 - must run LAST.
    Reads   : gene_counts_matrix.rds, normalized_counts.rds, vst_counts.rds,
              clean_sample_metadata.rds, size_factors.tsv,
              gene_variance_summary.tsv, sample_expression_summary.tsv
    Writes  : results/phase3_qc/reports/phase3_qc_report.txt
    Does    : sinks 9 sections into the report - dataset overview, gene
              filtering survey, normalization, sample QC (including the
              provisional retention of TCGA-BH-A0DZ__Tumor), matrix
              validation, batch-effect assessment guidance, the list of QC
              plots, the preprocessing decisions taken, and the limitations.

================================================================================
DEPENDENCY CHAIN (why this order and no other)
================================================================================

    4 -> 5 -> 6
    5, 6 -> 7, 8, 9, 10   (all read the raw matrix)
    5, 6 -> 11 -> 12      (DESeq2 objects, then VST)
    12 -> 13, 14, 15      (VST matrix / DESeqTransform object)
    5 + 11 + 12 -> 16     (needs all three matrices to compare)
    11 -> 17              (size_factors.tsv)
    7 + 9 + 11 + 12 + 16 -> 18   (the report reads everything, so it is last)
    1, 2, 3 are standalone: they only touch data/raw, so they run first
      simply to confirm the download is sound before anything is built.

Re-run rule: if you change script 4 or 5, everything from 5 onward must be run
again, because sample identity and matrix content feed all later stages.
